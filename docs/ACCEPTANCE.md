# 验收规则（20 条核心规则）与测试映射

规则编号与 `tests/status.test.ts` 一一对应，`npm test` 全量验证（28 个用例）。

## 一、进度状态规则

### R1 实际日期为空 ≠ 逾期 → 展示「待补实际日期」
- 任何节点实际日期为空，节点徽章显示「待补实际日期」，**不显示"已逾期"**
- 项目整体标记为「待补实际日期」（当无其他更高优先级状态时）
- 测试：`evaluateMilestone` 3 个用例

### R2 非验收节点计划日期已过且无实际日期 → 项目「有延期风险」
- 中间节点（非验收）计划日期早于今天且实际为空 → 项目状态 `LATE_RISK`
- 展示逾期天数与节点名称
- 测试：2 个用例

### R3 验收终审：项目完成只看「验收」节点
- 验收节点实际日期不为空 → 项目 `ACCEPTED`（已验收）
- 其他节点全完成但验收未填 → 不判定已完成
- 支持别名：验收 / 终验 / 结题 / 竣工验收 / 交付验收
- 测试：3 个用例

### R4 已验收项目从跟进/提醒中排除
- 已验收项目不再进入 7/14/30/60 天提醒与延期风险清单
- 测试：1 个用例

### R5 7 / 14 / 30 / 60 天到期窗口
- 未完成节点按计划日期距今天的天数归入对应窗口
- 已完成的节点、已逾期的节点不进入提醒窗口
- 测试：7 个用例

### R6 日期待核对
- 实际日期早于计划日期 → 标记
- 有实际日期但无计划日期 → 标记
- 实际日期晚于今天 → 标记
- 项目级优先显示「日期待核对」（高于已验收/延期）
- 测试：4 个用例

### R7 多 PM 拆分
- 分隔符：`/`、`、`、`，`、`,`、`;`、换行
- 自动去空白、去空值；按名称/账号关联用户
- 测试：2 个用例

### 其他状态
- 无任何节点 → 「未开始」
- 计划日期已过且实际日期已完成 → 不判延期
- 验收节点计划已过但未填实际 → 「待补实际日期」（验收终审语义）
- 测试：4 个用例

## 二、周报合并规则

### R8 按组聚合
- 周报成员按 A/B/C 三组聚合，生成 `【A组】/【B组】/【C组】` 三段文本与全量合并文本

### R9 保留原格式
- 每位成员的内容（本周工作 / 下周计划 / 问题风险）按原样保留换行、编号与符号，不重排

### R10 钉钉复制（不自动发送）
- 合并结果一键复制，可粘贴到钉钉/企鹅/邮箱；系统不发起任何自动消息

### R11 周次归属
- 以周一日期作为周次键（`mondayOf`），跨周互不干扰

### R13 服务端校验
- 所有 API 由中间件 + 路由双重校验会话；角色校验在服务端完成，不信任前端

### R14 密码安全
- bcrypt 哈希存储；登录失败记录审计

### R15 审计留痕
- 登录/登出/登录失败、项目增删改、导入、合并、导出均有审计日志

### R16 乐观锁
- 项目更新携带版本号；并发修改返回 409 冲突提示，避免覆盖

## 四、导入规则

### R17 工作表识别
- 优先读取「所有项目进度计划情况」，其次含"进度计划"的工作表，再次第一个工作表

### R18 表头自动识别
- 需包含项目名称列与至少一对「XX计划 / XX实际」列；列名兼容多写法

### R19 日期容错
- 支持 `2026-08-01`、`2026/8/1`、`2026年8月1日`、Excel 序列号；解析失败标记错误并跳过该行

### R20 导入模式
- 按名称更新（推荐，已存在项目更新节点）/ 清空后导入（危险，需确认）
